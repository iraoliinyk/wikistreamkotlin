Context
Project type: Kotlin + Spring Boot (not Go)
Go-specific tools mentioned (go vet, golangci-lint) → Map to Kotlin equivalents:
go vet → Kotlin linters: detekt, ktlint
golangci-lint → Gradle plugins: detekt (code analysis), ktlint (formatting)
Existing infrastructure: Docker Compose (local Cassandra), stored configs, Postman collection
Target registry: ghcr.io (GitHub Container Registry)

Step-by-Step Implementation Plan
Phase 1: Prepare the Kotlin Project for CI
1.1 Add code quality tools to Gradle
Add detekt plugin for static analysis (code smells, complexity, style issues)
Add ktlint plugin for Kotlin code formatting validation
Configure both to fail the build on violations (stricter than warnings)
Document which rules are enforced (team standards)

1.2 Create Gradle tasks for CI
Create a ciTest task that runs all unit tests
Create an integrationTest task that runs only integration tests (requires Docker/Cassandra)
Create a lintKotlin task that aggregates detekt + ktlint checks
Ensure tasks can run independently (for flexibility in CI stages)
1.3 Create/verify Docker build configuration
Confirm Dockerfile uses multi-stage build (already exists per README)
Verify builder stage has JDK 25 + Gradle cache
Verify runtime stage has minimal JRE 25 footprint (Alpine runtime image)
Add .dockerignore to exclude build artifacts, git files, test data
1.4 Prepare GitHub secrets
Document required GitHub Actions secrets:
GHCR_USERNAME (GitHub Actions token user, typically github.actor)
GHCR_TOKEN (GitHub Actions token with write:packages scope)
Any other registry credentials if needed

Phase 4: Docker Build & GHCR Publication
4.1 Image naming & tagging
Format: ghcr.io/owner/wikistreamkotlin:tag
Tags:
latest (on every merge to main)
Semantic version tag (e.g., v1.0.0, from Git tag or git describe)
Short commit SHA (e.g., abc1234)
Recommended tag variables in workflow:
IMAGE=ghcr.io/${{ github.repository_owner }}/wikistreamkotlin
SHORT_SHA=${GITHUB_SHA::7}
SEMVER_TAG=${GITHUB_REF_NAME} (only when ref type is tag)
4.2 Build step in CI
Run: docker build -t ghcr.io/owner/wikistreamkotlin:$TAG -f Dockerfile .
Optionally use Docker buildx for multi-platform builds (arm64 + amd64 if needed)
Cache layers between runs using actions/docker/setup-buildx@v2
Recommended buildx command pattern:
docker buildx build \
  --file Dockerfile \
  --tag $IMAGE:$SHORT_SHA \
  --tag $IMAGE:latest \
  --cache-from type=gha \
  --cache-to type=gha,mode=max \
  --push .
If SEMVER_TAG is present, add: --tag $IMAGE:$SEMVER_TAG
4.3 Push step (main branch only)
Step only runs if: github.ref == 'refs/heads/main' AND prior steps succeeded
Login to GHCR: use GitHub Actions docker/login-action@v2
Push: docker push ghcr.io/owner/wikistreamkotlin:latest + version tag
For pull_request events, build without push to validate Dockerfile only.
4.4 Workflow context secrets
${{ secrets.GITHUB_TOKEN }} (always available in GitHub Actions)
Use docker/login-action@v2 with registry=ghcr.io, username=github.actor, password=$GITHUB_TOKEN

Phase 5: Integration Test Strategy
5.1 Docker Compose in CI
Use docker-compose.yml (local Cassandra + Redis) or spawn containers inline
Start services before tests: docker compose up -d
Wait for health checks (Cassandra, Redis ready)
Run ./gradlew integrationTest
Collect reports from build/test-results/test/
Stop services: docker compose down
5.2 Test reporting
Upload JUnit XML reports from Gradle: build/test-results/test/*.xml
GitHub Actions Auto-publishes test results in PR checks
(Optional) Upload coverage reports to Codecov or SonarCloud
5.3 Artifact retention (optional)
Upload Docker image as artifact for debugging
Upload test logs if tests fail

Phase 6: Security & Best Practices
6.1 Dependency scanning
(Optional) Run Gradle dependency check: gradle dependencyCheck
(Optional) Use GitHub's built-in Dependabot for automated PRs on updates
6.2 Container scanning
(Optional) Scan published image for CVEs: trivy image ghcr.io/owner/...
6.3 Workflow security
Use permissions: write-packages (narrowly scoped, not write-all)
Rotate GitHub Token regularly
Never commit secrets; use GitHub Actions Secrets only

Success Criteria
When complete, the CI/CD pipeline should:
✅ On every PR to main:
Run unit tests → report results in PR checks
Run linting (detekt + ktlint) → block merge if violations
Run integration tests → report results
Build Docker image → verify no build errors
Do NOT push image to registry
✅ On merge to main:
Run all prior stages
Build final Docker image
Push to GHCR with tags: latest, semantic version (if tagged), short SHA
Publish completion notification (optional)
✅ Local testing with act:
Developer can run act -j unitTests locally before push
Developer can run full pipeline: act push --ref main to simulate merge
✅ Observability:
CI/CD logs visible in GitHub Actions UI
Test reports auto-published in PR
Image accessible at ghcr.io/owner/wikistreamkotlin:latest
